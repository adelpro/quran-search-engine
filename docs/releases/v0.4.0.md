# v0.4.0 — Subject Search, Multi-Term Search, and CLI

**Release date:** 2026-11-03
**Tag:** `v0.4.0`
**Package:** `quran-search-engine@0.4.0`

This release adds thematic (subject) search, independent multi-term search with ranking, and a
bundled command-line interface. The existing string-query API keeps working; the only required
code changes are for hand-built `SearchCounts` values and exhaustive `MatchType` switches.

## Highlights

- **Subject (thematic) search** — `loadSubjectData()`, `subjectMap`, `{ subject: true }`, and
  `matchType: 'subject'`. Maps English concepts (`"climate"`, `"worship"`) to curated Arabic
  lemma groups. The seed dataset covers 20 themes and is designed to grow.
- **Multi-term search** — `search(['محمد', 'يونس'])` runs each term independently through the full
  pipeline and merges by verse `gid`. Rank with `score` (default), `coverage`, or `frequency`.
- **CLI** — `npx quran-search-engine "رحم"`, with `--subject`, `--semantic`, `--regex`, `--sura`,
  `--juz`, `--format json|csv|tsv`, `--output`, and `--rank-by`.
- **Faster subject index** — `buildInvertedIndex()` reuses the root/lemma/word indices it already
  built instead of rescanning every verse per subject. The `subjectIndex` step drops from ~2.8s
  to ~0.36s on the shipped dataset.
- **Corrected counts** — lemma and root matches are scored again, so `counts.lemma` and
  `counts.root` are populated and the per-type counts add up to `counts.total`.
- **New validators** — `validateSubjectData()` and `validatePhoneticData()`.

## Bug fixes

- **Lemma/root matches were unscored** — `computeScore()` looked up `wordMap[token]` on a `Map`,
  so the entry was always `undefined`. Verses found only by the lemma or root layer were
  reported as `matchType: 'none'`, `counts.lemma`/`counts.root` stayed at `0`, and totals
  included unscored results (`العلم` showed 728 total but only 29 exact). The lookup now uses
  `wordMap.get(token)`. Exact matches also override earlier lemma/root matches in multi-word
  queries, and lemma matches return the verse word rather than the lemma for highlighting.
- **`suraName` with English or romanized names** — `suraName: 'Al-Fatiha'` used to match every
  romanized name containing a hyphen, and English names skipped filtering entirely. All three
  name forms now scope correctly.
- **Subject/semantic English queries** — `--subject climate` and `search('climate', { semantic:
true })` no longer transliterate the English word through the phonetic map. `--subject climate`
  now returns the 127 weather-theme verses instead of 2002 mostly-unscored hits.

## Boolean search

Boolean search is supported and auto-detected — no option is needed. The operators are symbols:

- `+term` — MUST
- `-term` — EXCLUDE
- `term | term` — EITHER/OR

Verified against the bundled dataset with `{ lemma: true, root: true, fuzzy: false }`:

| Query             | Linear scan | With `invertedIndex` |
| ----------------- | ----------- | -------------------- |
| `+الله -الرحمن`   | 1741        | 1571                 |
| `الله \| الرحمن`  | 1789        | 1616                 |
| `الله AND الرحمن` | 5           | 5                    |
| `الله NOT الرحمن` | 130         | 124                  |

The words `AND`, `OR`, and `NOT` are **not** operators. `OR` and `NOT` are dropped as unknown
non-Arabic tokens, so `'الله NOT الرحمن'` is an intersection of the two Arabic words. `AND`
resolves through the phonetic map to `عند`, so `'الله AND الرحمن'` searches three words. Counts
differ between the `invertedIndex` path (exact tokens) and the linear-scan fallback (substring
matching); use one path consistently.

## Breaking changes

1. `SearchCounts.subject` is required. Add `subject: 0` to object literals.
2. `MatchType` gained `'subject'`. Add a case to exhaustive switches.

Everything else is additive. See the
[Migration Guide](../migration-guide.md) for before/after examples.

```bash
npx quran-search-engine --version          # 0.4.0
npx quran-search-engine "climate" --subject --limit 3
npx quran-search-engine "[محمد, يونس]" --rank-by coverage --limit 3
```
